# Firebase Setup for Saved Items & Collections Feature

## Overview
This comprehensive guide will walk you through setting up the complete saved items and collections feature in your Firebase project. This feature allows users to bookmark campaigns/posts and organize them into custom collections (similar to Pinterest boards or browser bookmarks).

**Estimated Setup Time**: 10-15 minutes

**Prerequisites**:
- Firebase project created and connected
- Firestore Database enabled
- Authentication enabled (Email/Password, Google, etc.)
- Basic understanding of Firestore security rules

## Collections Structure

### 1. `savedItems` Collection
Stores all saved/bookmarked posts and campaigns by users.

**Document ID Format**: `{userId}_{itemId}`
- Example: `abc123_post456`

**Fields**:
```javascript
{
  userId: string,              // ID of the user who saved this
  itemId: string,              // ID of the post/campaign
  itemType: string,            // 'post' or 'campaign'
  title: string,               // Title of the saved item
  description: string,         // Description/summary
  imageUrl: string,            // Main image URL
  authorId: string,            // ID of the post author
  authorName: string,          // Name of the post author
  savedAt: timestamp,          // When it was saved
  collections: array<string>   // Array of collection IDs this belongs to
}
```

### 2. `collections` Collection
Stores user-created collections to organize saved items.

**Document ID**: Auto-generated by Firestore

**Fields**:
```javascript
{
  userId: string,              // ID of collection owner
  name: string,                // Collection name
  description: string,         // Optional description
  itemCount: number,           // Number of items in collection
  createdAt: timestamp         // When collection was created
}
```

## Step 1: Update Firestore Security Rules

Security rules ensure that users can only access and modify their own saved items and collections.

### How to Update Rules:

1. Go to [Firebase Console](https://console.firebase.google.com/)
2. Select your project
3. Navigate to **Firestore Database** → **Rules** tab
4. Copy the rules below and add them to your existing rules file

### Rules to Add:

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    
    // ============================================
    // SAVED ITEMS RULES
    // ============================================
    match /savedItems/{savedItemId} {
      // Helper function to check if user owns this saved item
      function isOwner() {
        return request.auth != null && 
               request.auth.uid == resource.data.userId;
      }
      
      // Helper function to validate saved item data
      function isValidSavedItem() {
        return request.resource.data.keys().hasAll(['userId', 'itemId', 'itemType', 'savedAt']) &&
               request.resource.data.userId is string &&
               request.resource.data.itemId is string &&
               request.resource.data.itemType in ['post', 'campaign'] &&
               request.resource.data.collections is list;
      }
      
      // Allow users to read their own saved items
      allow read: if request.auth != null && 
                     request.auth.uid == resource.data.userId;
      
      // Allow creating saved items if userId matches authenticated user
      allow create: if request.auth != null && 
                       request.auth.uid == request.resource.data.userId &&
                       isValidSavedItem();
      
      // Allow updating saved items (for adding/removing collections)
      allow update: if isOwner() && 
                       request.resource.data.userId == resource.data.userId;
      
      // Allow deleting own saved items
      allow delete: if isOwner();
    }
    
    // ============================================
    // COLLECTIONS RULES
    // ============================================
    match /collections/{collectionId} {
      // Helper function to check if user owns this collection
      function isOwner() {
        return request.auth != null && 
               request.auth.uid == resource.data.userId;
      }
      
      // Helper function to validate collection data
      function isValidCollection() {
        return request.resource.data.keys().hasAll(['userId', 'name', 'createdAt']) &&
               request.resource.data.userId is string &&
               request.resource.data.name is string &&
               request.resource.data.name.size() > 0 &&
               request.resource.data.name.size() <= 100;
      }
      
      // Allow users to read their own collections
      allow read: if request.auth != null && 
                     request.auth.uid == resource.data.userId;
      
      // Allow creating collections if userId matches authenticated user
      allow create: if request.auth != null && 
                       request.auth.uid == request.resource.data.userId &&
                       isValidCollection();
      
      // Allow updating collections (for item count, name changes)
      allow update: if isOwner() && 
                       request.resource.data.userId == resource.data.userId;
      
      // Allow deleting own collections
      allow delete: if isOwner();
    }
    
    // ============================================
    // YOUR OTHER EXISTING RULES GO HERE
    // (posts, users, notifications, etc.)
    // ============================================
  }
}
```

### Important Notes:
- **Don't replace** your entire rules file - just add the `savedItems` and `collections` sections
- Keep all your existing rules for posts, users, notifications, etc.
- The rules include validation to prevent malformed data
- Collection names are limited to 100 characters
- Only authenticated users can create/read/update/delete their own data

## Step 2: Create Firestore Indexes

Indexes are required for efficient querying of saved items and collections. Without them, queries will fail with an error.

### Why Indexes Are Needed:
- **Performance**: Indexes allow Firestore to quickly find documents matching your query criteria
- **Required for compound queries**: Any query filtering by 2+ fields needs an index
- **Automatic creation**: Firestore can auto-create indexes from error messages (recommended for beginners)

### The 3 Required Indexes:

### Index 1: Query saved items by user
- **Collection**: `savedItems`
- **Fields**:
  - `userId` (Ascending)
  - `savedAt` (Descending)

### Index 2: Query saved items by user and collection
- **Collection**: `savedItems`
- **Fields**:
  - `userId` (Ascending)
  - `collections` (Array-contains)
  - `savedAt` (Descending)

### Index 3: Query collections by user
- **Collection**: `collections`
- **Fields**:
  - `userId` (Ascending)
  - `createdAt` (Descending)

### How to Create Indexes (Choose One Method):

#### **Method 1: Automatic via Error Messages (EASIEST - RECOMMENDED)**

This is the simplest method for beginners:

1. **Skip manual index creation for now**
2. Run your app and try to use the saved feature
3. Open browser DevTools Console (F12)
4. When you try to save an item or view saved items, you'll see an error like:
   ```
   The query requires an index. You can create it here: https://console.firebase.google.com/...
   ```
5. **Click the link** in the error message
6. It will open Firebase Console with the index form **already filled out**
7. Click "Create Index"
8. Wait 2-5 minutes for the index to build
9. Refresh your app and try again
10. Repeat for each of the 3 indexes (they'll appear one at a time as you use different features)

**This method is foolproof and prevents typos!**

If you're using Firebase CLI for deployment:

2. Add this configuration:

```json
      },

        "queryScope": "COLLECTION",
        "fields": [

          { "fieldPath": "savedAt", "order": "DESCENDING" }
        ]
      },
      {
        "collectionGroup": "collections",
        "queryScope": "COLLECTION",
        "fields": [
          { "fieldPath": "userId", "order": "ASCENDING" },

      }

```

3. Save the file
4. Install Firebase CLI if you haven't: `npm install -g firebase-tools`
5. Login: `firebase login`
6. Initialize (if not done): `firebase init firestore`
7. Deploy indexes: `firebase deploy --only firestore:indexes`
8. Wait 2-5 minutes for indexes to build

### Checking Index Status:

After creating indexes:
1. Go to Firebase Console → Firestore → Indexes tab
2. You should see 3 indexes with status:
   - 🟡 **Building** (wait a few minutes)
   - 🟢 **Enabled** (ready to use!)

### Index Build Time:
- Empty database: ~30 seconds
- Small database (<1000 docs): ~2-5 minutes
- Large database (>10,000 docs): ~10-30 minutes

**Tip**: Create indexes before adding test data to speed up build time!

## Common Issues & Solutions

### 🔴 Issue: "Missing or insufficient permissions"

**Error Message**: 
```
FirebaseError: Missing or insufficient permissions.
```

**Causes**:
- Security rules not deployed
- User not logged in
- Trying to access another user's data

**Solutions**:
1. **Check if rules are deployed**:
   - Go to Firebase Console → Firestore → Rules
   - Verify you see the `savedItems` and `collections` rules
   - Check "Last deployed" timestamp
   - If rules are old, click "Publish" again

2. **Verify user authentication**:
   ```javascript
   // Add this to your console
   import { getAuth } from 'firebase/auth';
   console.log('Current user:', getAuth().currentUser);
   ```
   - If null, user is not logged in - redirect to login page

3. **Check userId matches**:
   - Open browser DevTools → Network tab
   - Filter by "firestore"
   - Look at the request payload
   - Verify `userId` matches your auth UID

### 🔴 Issue: Collections count not updating

**Symptom**: Collection shows wrong number of items

**Cause**: itemCount field out of sync

**Solution**:
The `addToCollection` and `removeFromCollection` functions automatically recalculate the count. If it's still wrong:

1. **Manual fix via Firebase Console**:
   - Go to the collection document
   - Count how many saved items have this collection ID in their `collections` array
   - Manually update the `itemCount` field

2. **Rebuild function** (add to `savedItems.js`):
   ```javascript
   export const rebuildCollectionCounts = async (userId) => {
     const collections = await getUserCollections(userId);
     const savedItems = await getSavedItems(userId);
     
     for (const collection of collections) {
       const count = savedItems.filter(item => 
         item.collections?.includes(collection.id)
       ).length;
       
       await updateDoc(doc(db, 'collections', collection.id), {
         itemCount: count
       });
     }
   };
   ```

### 🔴 Issue: "Document already exists" error

**Error Message**:
```
FirebaseError: Document already exists
```

**Cause**: Trying to save the same item twice

**Solution**: 
This is expected behavior! The error should be caught silently. If it's showing to users:

```javascript
// In PostCard.jsx, update handleSave:
try {
  if (isSaved) {
    await unsaveItem(currentUser.uid, post.id);
    setIsSaved(false);
  } else {
    // Use set with merge instead of create
    await saveItem(currentUser.uid, post.id, 'post', {...});
    setIsSaved(true);
  }
} catch (error) {
  if (error.code === 'already-exists') {
    // Silently handle - item is already saved
    setIsSaved(true);
  } else {
    console.error('Error toggling save:', error);
    alert('Failed to save item. Please try again.');
  }
}
```

### 🔴 Issue: Slow loading on Saved page

**Symptom**: Saved page takes 5+ seconds to load

**Causes**:
- Many saved items (100+)
- Large images
- Inefficient queries
- Missing indexes

**Solutions**:

1. **Verify indexes are enabled** (most common cause)
2. **Add pagination**:
   ```javascript
   // In getSavedItems, add limit:
   const q = query(
     collection(db, 'savedItems'),
     where('userId', '==', userId),
     orderBy('savedAt', 'desc'),
     limit(50) // Only load 50 at a time
   );
   ```

3. **Implement lazy loading**:
   - Load images on scroll
   - Use `loading="lazy"` on img tags

4. **Cache results**:
   ```javascript
   // Use React Query or SWR for caching
   const { data: savedItems } = useQuery(
     ['savedItems', userId],
     () => getSavedItems(userId),
     { staleTime: 5 * 60 * 1000 } // Cache for 5 minutes
   );
   ```

### 🔴 Issue: Real-time updates not working

**Symptom**: Changes don't appear without manual refresh

**Note**: Currently the feature uses `getDocs` (one-time read), not `onSnapshot` (real-time).

**To add real-time updates**:

```javascript
// In Saved.jsx, replace getDocs with onSnapshot:
import { onSnapshot } from 'firebase/firestore';

useEffect(() => {
  if (!currentUser) return;
  
  const q = query(
    collection(db, 'savedItems'),
    where('userId', '==', currentUser.uid)
  );
  
  const unsubscribe = onSnapshot(q, (snapshot) => {
    const items = snapshot.docs.map(doc => ({
      id: doc.id,
      ...doc.data()
    }));
    setSavedItems(items);
  });
  
  return () => unsubscribe();
}, [currentUser]);
```

## Performance Optimization Tips

### 1. Image Optimization
- Compress images before uploading (use tools like TinyPNG)
- Use appropriate image sizes (don't load 4K images for thumbnails)
- Implement lazy loading

### 2. Query Optimization
- Always use indexes for compound queries
- Limit query results (add `.limit(50)`)
- Cache frequently accessed data
- Use pagination for large datasets

### 3. State Management
- Consider using React Query or SWR for server state
- Implement optimistic updates (update UI before Firestore confirms)
- Debounce rapid operations (like clicking bookmark repeatedly)

### 4. Code Splitting
- Lazy load the Saved page:
  ```javascript
  const Saved = lazy(() => import('./pages/user/Saved'));
  ```

### 5. Firestore Best Practices
- Avoid reading entire collections
- Use field-level updates instead of full document overwrites
- Batch write operations when possible
- Monitor usage in Firebase Console to avoid quota limits

## API Reference

All utility functions are in `src/utils/savedItems.js`:

- `saveItem(userId, itemId, itemType, itemData)` - Save an item
- `unsaveItem(userId, itemId)` - Remove saved item
- `isItemSaved(userId, itemId)` - Check if item is saved
- `getSavedItems(userId, collectionId?)` - Get all saved items, optionally filtered by collection
- `createCollection(userId, name, description?)` - Create a new collection
- `getUserCollections(userId)` - Get all user's collections
- `addToCollection(userId, itemId, collectionId)` - Add item to collection
- `removeFromCollection(userId, itemId, collectionId)` - Remove item from collection
- `deleteCollection(collectionId)` - Delete a collection

## Firestore Quota & Pricing

### Free Tier Limits (Spark Plan):
- **Stored data**: 1 GiB
- **Document reads**: 50,000/day
- **Document writes**: 20,000/day
- **Document deletes**: 20,000/day

### Estimated Usage for Saved Items:

**Per user per day**:
- Loading saved page: ~1-10 reads (depending on saved items count)
- Creating collection: 1 write
- Saving item: 1 write
- Unsaving item: 1 delete
- Adding to collection: 2 writes (savedItem + collection)

**For 1,000 daily active users**:
- If each loads saved page once: 1,000-10,000 reads
- If 10% save an item: 100 writes
- Well within free tier limits!

**When you might need to upgrade**:
- 5,000+ daily active users
- Users with 100+ saved items each
- Implementing real-time updates (uses more reads)
- Frequent collection reorganization

### Cost Optimization:
- Use pagination (limit queries)
- Implement caching
- Batch operations when possible
- Use `getDocs` instead of `onSnapshot` unless real-time is critical

### From Another Bookmarking System:

```javascript
// Example: Migrate from simple array-based bookmarks
export const migrateOldBookmarks = async (userId, oldBookmarks) => {
  const batch = writeBatch(db);
  
  oldBookmarks.forEach(bookmark => {
    const savedItemRef = doc(db, 'savedItems', `${userId}_${bookmark.postId}`);
    batch.set(savedItemRef, {
      userId,
      itemId: bookmark.postId,
      itemType: 'post',
      title: bookmark.title || '',
      description: bookmark.description || '',
      imageUrl: bookmark.imageUrl || '',

};
```
